# 网页表现层：ASCII 烘焙像素 + PixiJS + CRT 着色器

网页端的全部画面，包括菜单，都绘制在一块 PixiJS 画布上：场景先渲染到 640×360 的渲染纹理，按整数倍放大到屏幕，再在屏幕分辨率上执行全屏 CRT 后处理（扫描线、荧光余辉、辉光、暗角、曲率）。像素资产沿用"ASCII 或形状指令烘焙成像素网格"的思路；烘焙与渲染器无关，PixiJS 只负责把烘焙结果作为最近邻过滤的纹理绘制出来。资产里的字符表示荧光亮度等级而不是具体颜色，由 CRT 着色器统一染成琥珀色，保证画面单色一致，也能用一个参数切换荧光颜色。

## Considered Options

- DOM + CSS：文字排版最省事，但做不出荧光余辉等真正的 CRT 质感。
- 纯 Canvas2D：在屏幕分辨率上逐像素做 CRT 后处理太慢，只能用 CSS 叠层近似。

## Consequences

- 补间动画产生的坐标一律取整；纹理全局使用最近邻过滤。
- 中文像素字体按设计字号绘制在整数坐标上；若仍有抗锯齿灰边，改为预烘焙去灰字形图集。
- 落地第一步先做小验证：烘焙精灵是否像素锐利、中文像素字体是否清晰、带余辉的 CRT 着色器能否运行。若 PixiJS 走不通，退路是"Canvas2D 绘制场景 + 一段原生 WebGL 只做 CRT 后处理"。
