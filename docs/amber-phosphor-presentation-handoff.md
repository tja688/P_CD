# The Call Amber Phosphor CRT 表现层接力手册

> 本文是网页表现层的唯一接力入口。后续修改 `src/Pcd.Web` 前先读本文、`CONTEXT.md`、`docs/adr/0010-web-presentation-pixi-with-baked-ascii.md`，再读对应源码。

## 1. 已落地的设备想象

The Call 的网页不是现代网页套一层橙色滤镜，也不是用 CSS 拼出来的机箱。玩家面前只有一块亮在黑暗里的琥珀磷光屏幕，屏幕里的图形仍是 **PALISADE A–09** 终端解出来的内容：

- 网页底色是自然的深黑。屏幕里的“黑”是显像管玻璃自己的暖褐，比四周环境更浑、更暖。
- 屏幕四周没有铭牌、螺钉、通风槽、金属外框或全屏按钮。边缘用暗部渐隐进网页底色，不出现硬切边。全屏函数留在 `window.terminal.toggleFullscreen`，需要时再接到屏幕内的校准界面。
- 画面内部是 640×360 的逻辑显像面；场景、卡图、边框和文字先在此分层绘制，再通过 CRT 后处理显示。
- 灰度帧缓冲是视觉资产的中间语言。最终颜色由 CRT 映射为琥珀色，因此内容插画不允许携带彩色语义。
- 卡牌不是纸牌 UI。每张牌是由终端登记的“图形记录”，卡牌构图使用扫描、机械结构、仪器、人物轮廓、符号和抖色来表达其能力。
- 怪物不是头像。怪物是被接收系统记录的异常接触体，使用机械肖像和检视图表达。

当前可运行入口：

```text
http://127.0.0.1:5180/
```

启动：

```bash
dotnet run --project src/Pcd.DevHost
```

## 3. 逻辑画面和坐标

逻辑画布固定为 `640×360`。浏览器画布可以按整数倍放大，CRT 显示层再根据屏幕尺寸适配。所有逻辑坐标必须是整数：

```js
source.width = 640
source.height = 360
ctx.imageSmoothingEnabled = false
```

当前区域约定：

- `x=20..620`：安全内容区。
- `y=16..31`：页眉。只放当前章节或回合，不放载波编号、版本、状态灯，也不重复游戏名。
- 没有页脚。不放常驻铭文、操作提示或和画面重复的英文标签。规则说明只在手册里。
- 主页左侧是天线主图形，右侧是 THE CALL 和开始、继续、卡盒、校准。不叠加点阵框，不放口号。
- 关卡选择是三列肖像和名字，下面是牌组、张数、负荷和开始。
- 对局九宫格使用 `173..434`，`y=42` 起，每格 83×64，按 1 到 9 行优先。格内图形用 40×32 的亮部缩图，名字独占底行。合法格只亮框，不写 PLACE。
- 怪物点数跟在左侧肖像旁，玩家点数在左下，和牌库、手牌、弃牌、结束回合放在一起。
- 对局右侧只在正在查看一张牌时出现：图、名字、点数或「法术」、规则文字。没有文字就不写「无附加能力」。
- 对局底部 `y≈270` 起是手牌。演出不在底部叠字幕；点数变化只在格位上闪差值。

新增场景先画结构线、区域框和信息优先级，再画装饰。框线、文字和插画不能相互覆盖。能用亮度和位置说明的，不加一句解释。

## 4. MASTER 磷光色板

场景帧缓冲只能使用六级中性灰：

| 等级 | 色值 | 用途 |
| --- | --- | --- |
| 0 | `#080808` | 黑玻璃、空洞、未激活区域 |
| 1 | `#242424` | 背景结构、深阴影、低亮网纹 |
| 2 | `#505050` | 普通轮廓、金属暗面、次级信息 |
| 3 | `#888888` | 中间体积、普通正文、机械表面 |
| 4 | `#bcbcbc` | 选中框、重要轮廓、亮面 |
| 5 | `#f0f0f0` | 锐利亮核、关键数字、信号峰值 |

`crt.js` 把灰度映射成过驱琥珀磷光。暗部留在深褐玻璃里，中间亮度是饱和琥珀，峰值亮核推向白热金，光晕从亮核向外落到更深的琥珀。不要添加蓝色、紫色或另一套彩色稀有度。稀有度只能通过边框密度、信息标记、图形复杂度和亮度层级表达。

色板的感受应是“厚重、机械、温暖、神秘、可信”，再加一层显像管被推亮后的磷光泛光。亮的地方要发光，暗的地方仍是暗玻璃。不是橙色网页、橙色霓虹灯或纯黑终端，也不要把整屏抬成一片灰橙。

## 5. 图形创作规则

### 5.1 卡牌

`art.js` 中 `motifs` 的索引和内容 ID 一一对应：`card.c001` 到 `card.c051` 使用卡牌数字索引；`card.m001` 到 `card.m003` 使用机械异常体分支。新增卡牌时必须：

1. 读取 `content/rules/catalog.yaml` 的名称、学校、点数、能力和文字。
2. 为能力选一个视觉主语：采样机、瞄准器、投影、坟墓、护盾、圣徽、计时器、终端、人物或场景装置。
3. 使用至少三种几何层：轮廓、实体积、网纹/抖色或高光。
4. 使用明确的前景、中景和背景关系，避免只画一个居中的小图标。
5. 在卡图中保留 `id` 的小型登记标记和角落框线，但不在插画里重复长篇规则文字。
6. 用 `drawArt(ctx,id,x,y,w,h)` 绘制；不让调用方知道内部缓存。图形像素是 2（`draw.js` 的 `PX`）：边框、图标、卡面和主视觉都落在这个网格上，最近邻绘制，不把插画拉成不成整数关系的矩形。文字保持 1px，是图形像素的二分之一。卡面和怪物肖像的原生尺寸是 48×48，主视觉是 288×252。卡面来自 `plates.js` 的灰阶精灵；卡背是同网格上的几何印记。

卡面图形是低分辨率 bitmap/dither 记录。优先用 `rect`、`line`、`poly`、`ell`、`ring`、`prism`、`dither`；斜线要有目的，不能把密集斜线当作万能纹理。

13 种已有卡背通过 `cardBack()` 生成独立几何印记，在卡盒“卡背”页只读检视真实负荷、点数增量和能力。现有内核构建牌组尚无卡背输入接口，不提供装备按钮。

### 5.2 怪物

三个现有怪物必须有不同的视觉性格：

- `monster.001` 失控机械：面板脸、液压肋骨、左右肩结构和扫描光学组件，表现“失控的工业自动机”。
- `monster.002` 活数据库：更多阵列、条带显示器、数据缓存和规则化面板，表现“仍在学习的冷静系统”。
- `monster.003` 废燃泰坦：重型外壳、宽肩、天线/燃烧炉和粗大连接件，表现“污染环境中的巨大热源”。

如果后续扩展怪物，必须先写一个视觉动词，例如“压缩”“复制”“污染”“回收”，再决定肖像结构。不要只更换颜色。

### 5.3 主图形

主页 `hero` 是远方接收站：抛物面天线、馈源、山脊、一道信号圆环和地面设备。它是 The Call 的视觉记忆点。保持横向构图，留出右侧标题的信息呼吸空间。圆环、刻度和地面线要少而清楚，不要用密铺斜线、同心圆或点阵把天空填满。不要在图里印经纬度、站名或编号。可以增加天气和接收波形，但不能变成风景插画或现代营销 Hero。怪物肖像同样不印 OPTICAL RECORD 这类说明。

## 6. CRT 显像管线

`CRT` 有两个阶段：

1. 把源帧上传到 640×360 的纹理。
2. 使用两个历史纹理交替保存余辉，再把结果通过显示 shader 映射到设备画布。

显示分三步：

1. 信号按逻辑像素中心做最近邻采样。一颗 640×360 的像素在放大后仍是一整块，扫描线和光晕都不得把它从中间切开。
2. 只把归一化亮度 0.70 以上的高光抽到 320×180，做一次可分离高斯。普通正文和 1 级底纹不进入这层。
3. 合成时亮核最亮，邻接像素只留一圈更暗的磷光边，半分辨率光晕加在暗玻璃上，并且按本像素亮度衰减。光晕再强也不能追平笔画中心。行扫描按整行逻辑像素轻轻压暗，大约 6%，不再对最终颜色做第二次扫描。

另外保留：

- 暗褐玻璃底。黑位不抬成灰橙。
- 温和的曲面坐标变形。
- 低强度、慢速、偶发的局部信号漂移。
- `prefers-reduced-motion` 或“静态舒适”设置下关闭时间扰动和余辉运动。泛光仍保留。

设计边界：

- 清晰来自对比，不来自把画面涂亮。参考图里大字能数出像素，光晕是字外面的暗琥珀，密集处会暖，但笔画中心始终更接近白热金。
- 标准观感仍是过驱磷光：亮核发白，光晕向外溢出。溢出的是高光，不是整张灰度图。
- CRT 效果仍要让 12px 中文和 1px 框线可读。泛光可以贴着笔画外缘，不能把笔画和间隙糊成同一块亮度。
- 长时间看不应有全屏闪烁、随机白闪或快速抖动。颗粒只做细砂，不能吃掉字形边缘。
- 单色设备不使用 RGB 色差，也不使用按输出像素交替的孔径光栅。
- 任何 shader 改动都必须保留 `mapPoint(clientX,clientY)` 的命中逆变换。
- WebGL 不可用时，`CRT` 必须把逻辑画布做成带泛光的琥珀画面并铺满显示，不得返回空黑画面。降级路径使用同一套高光阈值和亮核优先的合成。

可调参数：

```js
{
  bloom: 1,
  curvature: 0.30,
  persistence: 0.50,
  noise: 0.70,
  reducedMotion: false,
  brightness: 0.90,
  power: 1
}
```

`bloom` 只放大笔画外的近距光边和半分辨率高光晕，不负责把暗部提亮，也不能把光晕抬到与亮核相同的亮度。`brightness` 提高整条曝光，标准值 `0.9` 时峰值应接近白热金。终端校准里的「内敛 / 磷光 / 过驱」对应 `bloom` `0.5 / 1 / 1.5`，「柔和 / 标准 / 明亮」对应 `brightness` `0.6 / 0.9 / 1.2`。

旧的淡磷光配置存在 `localStorage` 的 `call.settings` 里。保存的对象缺少 `phosphor: "flare-3"` 时，启动会改写亮度、泛光、曲面、余辉和颗粒，并保留音量、静音和静态舒适选择。判断必须看读出来的旧值，不能看和默认值合并之后的结果。

## 7. 交互和演出

交互不是 DOM 卡片点击，而是对屏幕上的图形记录发送操作。`app.js` 维护逻辑 hit table，同时把合法 hit 转成隐藏但可聚焦的语义按钮，因此鼠标、触摸、键盘和辅助技术共享同一套动作。

当前操作：

- 点击或 Tab：聚焦控件。
- Enter：确认隐藏语义控件。
- `1..7`：选择当前可见手牌。
- 选牌后 `1..9`：发送到对应合法格位。
- `E`：结束回合。
- `Escape`：取消选择、关闭模态框或打开暂停菜单。
- `F1`：操作手册。
- `F8`：把当前对局记录写到桌面。演出进行中、报错弹窗和暂停菜单里都可以按。记录包含录像、快照、玩家看到的局面、被内核拒绝的操作和错误原文。
- `Space`：加速事件演出，但不改变规则结果。
- 声音开关在屏幕内的「终端校准」。全屏没有网页按钮；`toggleFullscreen()` 保留给以后的屏内入口。

事件演出必须消费内核 `GameEvent`：

- `card-entered`：格位亮核、短促入场声。
- `card-played`：发送/施放确认声。
- `points-changed`：点数亮核、机械冲击声。
- `card-removed`：离场和较低频下降声。
- `card-drawn`：短促读取声。
- `intent-revealed`：怪物意图载波声。
- `status-changed`：状态标记更新。
- `resource-changed`：资源数字更新。
- `cell-polluted`：格位网纹改变。
- `match-ended`：胜利上行和失败下行序列。

事件展示可以延迟或加速；不能改变事件顺序、合法选项或快照。画面上不叠事件字幕。点数变化只在对应格位闪一下差值。字幕文本仍写入对局记录，供导出使用。

## 8. 规则接入边界

`src/Pcd.DevHost/Program.cs` 是 HTTP Adapter：

```text
GET  /api/catalog
POST /api/start
POST /api/answer
POST /api/trace
```

`/api/catalog` 由宿主读入 `content/rules/catalog.yaml` 后调用 `ContentCatalog.Parse` 产生，包含全部真实卡牌、怪物、牌组、状态和资源。`/api/start` 创建 `MatchSession`；`/api/answer` 从 snapshot 恢复并提交一个合法选项。怪物待决策由已有 `MonsterAi` 自动推进到玩家待决策或结算。`/api/trace` 只把浏览器交来的对局记录原样写到桌面，不参与规则。

前端可读取：

- `view`: 当前公开视图和玩家手牌。
- `pending`: 内核提出的待决策与全部合法选项。
- `events`: 这次推进新增的事件。
- `steps`: 事件演出用的阶段序列。
- `snapshot`: 下一次 `/api/answer` 所需的不透明快照。
- `replay`、`hash`、`result`: 录像和结果。

前端不得：

- 自己计算合法格位。
- 因为卡牌名称或点数猜测效果。
- 读取或显示 `omniscient` 信息。
- 把未实现的商店、大地图或奖励系统做成能点击但没有规则的假功能。
- 修改 `MatchSession` 的状态以驱动画面。

需要规则新能力时，先修改内核和内容，再让表现层消费新的事件/视图字段。

## 9. 内容 ID 与主题

代码使用 `card.c001` 这类内容 ID，不能把中文工作名写成逻辑 key。中文名称来自内容目录，`CardText.Render` 生成卡牌文字。主题后续可以替换名称、美术和声音，但以下骨架不可因换主题而改变：九宫格、点数、覆盖、手牌、牌组、弃牌堆、出牌机会、回合和意图。

当前 `/api/catalog` 返回 54 条卡牌定义：51 张 `card.c###` 玩家卡牌与 3 张 `card.m###` 怪物初始卡。卡盒可编辑玩家卡牌，并在“卡背”页检视全部 13 种卡背。`MatchSetup.BuildDeck` 目前仅接收卡牌 ID，网页不冒充已经接通卡背装备流程。

新增内容的完整检查：

- `catalog.yaml` 有内容定义和合法能力。
- `art.js` 有相同 ID 的原创图形分支。
- API catalog 能返回它。
- 卡盒筛选和分页能显示它。
- 真实对局中至少经历一次该卡的可见路径。
- 事件演出对其相关 `GameEvent` 有可读表现。
- 不新增另一套卡牌文字或规则解释源。

## 10. 完成前验证

每次表现层改动必须至少执行：

```bash
node --check src/Pcd.Web/app.js
node --check src/Pcd.Web/art.js
node --check src/Pcd.Web/crt.js
node --check src/Pcd.Web/draw.js
node --check src/Pcd.Web/audio.js
dotnet build src/Pcd.DevHost/Pcd.DevHost.csproj
dotnet test Pcd.slnx --no-restore
```

Windows 下宿主运行时会锁住自己的输出文件。修改 `Pcd.DevHost` 后先停止旧进程，再构建并重新启动。当前浏览器实测覆盖 1280×900、1480×1040 与 900×650；手机窄宽属于后续改动的验收要求，不应把 CSS 适配推断成已通过实际触屏验收。

运行实际网页并观察：

```bash
dotnet run --project src/Pcd.DevHost
```

浏览器验收清单：

- 主页、关卡选择、卡盒、对局和结算都不是黑屏。
- 主页天线图和三种怪物图形可辨识，卡盒 51 张内容全部能翻页。
- 选择真实卡牌后，合法格位由内核返回并可点选。
- 法术会进入目标选择；`choose-card` 与 `choose-cell` 不穿透到底层画布。
- 刷新页面可以继续本机保存的玩家待决策。
- 三个牌组 × 三个怪物均能通过 API 实际推进到 `result`。
- 900×650 和手机窄宽下无水平溢出，文字不越出容器。
- WebGL 路径和强制无 WebGL fallback 都有可见琥珀画面。
- 开启静态舒适后不再产生连续时间扰动；声音可静音。
- `window.terminal.inspect()` 只用于本地验收，不应成为玩家 UI 的规则来源。

内核改动仍须遵守仓库要求：规则场景测试、内容校验、不变量随机测试和 .NET/WebAssembly 一致性测试。

## 11. 接力决策顺序

面对后续视觉需求时按以下顺序做决定：

1. 先确认它属于规则、内容、表现还是设备壳；把改动放在最深且最合适的模块。
2. 先复用 `Draw`、`art.js`、`CRT` 和 `TerminalAudio` 的接口，不在场景文件里重写像素、色板或 shader。
3. 先设计亮度等级和构图，再写绘制代码。
4. 先接真实 catalog/view/event，再做演出；不存在的内核能力要明确写出，不做静态假状态。
5. 修改后实际打开浏览器看画面，再跑特定交互和自动化检查。
6. 发现风格漂移时优先修正亮度层级、像素尺度、信息密度、边框节奏和设备语义，不靠增加橙色或扫描线掩盖问题。

最终目标不是“有 CRT 滤镜的卡牌网页”，而是玩家相信自己正在操作一台有历史、有故障边界、有物理显示逻辑的 A–09 图形终端。
